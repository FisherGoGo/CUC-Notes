# 信息论与编码数字教材设计

## 1. 项目目标

将现有《信息论与编码》六章笔记整理为一个可公开分享的静态阅读网站。网站服务于知识点浏览和系统阅读，不承担刷题、在线计算或交互实验功能。

核心目标：

- 六章内容完整覆盖；
- 先展示直觉、定义与结论，长推导按需展开；
- 公式排版可靠，桌面端和手机端均易读；
- 每个知识点可通过独立 URL 直接分享；
- 部署到 GitHub Pages，不依赖后端、账号或数据库。

## 2. 已确认的产品边界

### 包含

- 六章数字教材：信源、离散信道、编码、限失真、有噪信道编码、纠错编码；
- 章节导航、本节导航、全文搜索和知识点锚点；
- 使用浏览器原生折叠组件展开完整推导；
- 数学公式、图片、图注、符号说明、易错点和跨章节相关链接；
- GitHub Pages 静态部署。

### 不包含

- 概率拖拽、曲线模拟、编码计算器等交互实验；
- 题库、答题、评分和学习进度系统；
- 用户账号、评论、云端同步、数据库和服务端 API；
- 从原始笔记自动同步内容。

网页内容与 `大二下/信息论与编码/01_笔记` 中的 Markdown 独立维护。原笔记仅作为首次迁移与校对依据。

## 3. 信息架构

网站采用三栏阅读桌布局。

### 左栏：全局导航

- 展示六章目录与各章小节；
- 标记当前章节；
- 支持前后章节跳转；
- 桌面端固定显示，手机端收进导航抽屉。

### 中栏：正文

每个知识点采用统一顺序：

1. 一句话直觉；
2. 核心定义或结论；
3. 关键公式；
4. 符号说明；
5. 可展开的完整推导；
6. 易错点；
7. 相关知识。

定义、结论和关键公式始终可见。较长证明与推导默认折叠，使用原生 `<details>` 元素实现；即使 JavaScript 不可用，内容仍可访问。

### 右栏：页内导航

- 展示当前知识点的页内目录；
- 提供符号速查和相关知识链接；
- 桌面端随阅读位置更新，手机端收进页内目录抽屉。

### 顶部工具区

- 全文搜索；
- 公式或符号关键词检索；
- 复制当前知识点链接；
- 手机端的章节目录与页内目录入口。

每个知识点拥有稳定、可读的独立路径或锚点。分享链接后应直接定位到对应内容，而不是只打开首页。

## 4. 视觉设计

视觉方向为“学术编辑风”。

- 使用暖纸色背景和高对比深色正文；
- 标题使用适合中文的衬线字体，正文优先使用清晰的系统字体；
- 以克制的砖红色标记当前位置、重点和链接；
- 公式区使用轻微底色或细边线，不使用大面积卡片；
- 通过字号、段间距、细分隔线和留白建立层级；
- 避免渐变、玻璃拟态、悬浮装饰、持续动画和仪表盘式布局。

桌面端保留三栏效率；小屏幕只显示单栏正文，两侧导航按需呼出。正文宽度需控制在适合长时间阅读的范围内。

## 5. 内容组织

站点内容按章拆分为独立 MDX 文件，并使用统一的元数据描述标题、顺序、摘要和前后章节关系。网页内容可以针对阅读体验重写层级和导语，但迁移时不得擅自改变原笔记中的公式、定理条件和结论。

现有图片（包括 Fano 不等式相关图像）复制到站点静态资源目录，并补充：

- 简明图注；
- 可访问的替代文本；
- 明确的来源章节；
- 在手机端不溢出的尺寸规则。

章节通过“前置知识”和“接下来学习”链接形成轻量关联，不建设复杂知识图谱。

## 6. 技术架构

### 构建与渲染

- 使用 Astro 构建纯静态站点；
- 使用 MDX 承载独立维护的课程内容；
- 使用 KaTeX 在构建阶段渲染 LaTeX 数学公式；
- 仅为搜索、移动导航和复制链接加载少量客户端 JavaScript；
- 输出静态 HTML、CSS、JavaScript 和图片资源。

### 内容数据流

1. 作者编辑站点内的 MDX 章节；
2. Astro 读取章节元数据并生成目录、前后章关系和静态页面；
3. KaTeX 在构建阶段生成公式标记；
4. 静态搜索工具根据最终页面生成本地索引；
5. 构建产物部署到 GitHub Pages；
6. 访问者直接从静态文件读取页面，无运行时服务依赖。

### 部署

- 使用 GitHub Actions 构建并发布 GitHub Pages；
- 正确配置仓库子路径，确保资源、搜索索引和深层页面均可访问；
- 构建产物不手工提交到内容目录。

## 7. 故障处理

该网站没有运行时数据请求，因此故障重点放在构建期发现。

- KaTeX 无法解析公式时，构建失败并指出源文件；
- 内部链接或图片路径失效时，检查任务失败；
- 章节缺少标题、顺序等必填元数据时，构建失败；
- 搜索脚本不可用时，正文与目录仍应正常阅读；
- 客户端 JavaScript 不可用时，原生推导折叠仍可操作，所有正文仍存在于 HTML；
- 自定义字体加载失败时回退到本地系统字体，不影响排版结构。

## 8. 验证与验收

### 自动检查

- Astro 生产构建成功；
- TypeScript 与代码质量检查通过；
- 公式解析无错误；
- 内部链接和静态资源路径有效；
- 六章及其必需元数据均存在；
- GitHub Pages 子路径下的生产预览可访问。

### 浏览器检查

- 桌面端三栏布局清晰且正文宽度适中；
- 手机端正文为单栏，两个导航入口可操作；
- 公式不横向破坏页面，必要时可在公式容器内滚动；
- 推导可展开、收起并通过键盘操作；
- 全文搜索可定位到知识点；
- 复制的知识点链接可直接打开正确位置；
- 图片具有替代文本，正文颜色和焦点状态满足基本可访问性要求。

### 内容验收

- 六章知识点均已迁移；
- 公式、定理条件和结论与原笔记逐章核对；
- 每个知识点至少包含直觉说明、核心内容和必要的推导入口；
- 不出现占位内容、空章节或无说明的图片。

## 9. 完成标准

当六章内容全部上线，生产构建和质量检查通过，并在桌面端与手机端验证导航、搜索、公式、折叠和分享链接后，第一版视为完成。
