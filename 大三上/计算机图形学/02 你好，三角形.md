# VBO

VBO 就是把 CPU 里的顶点数据，复制到 GPU 的 Buffer 里，供后面的顶点着色器读取

~~~c++
float vertices[] = {
    -0.5f, -0.5f, 0.0f,
     0.5f, -0.5f, 0.0f,
     0.0f,  0.5f, 0.0f
};

unsigned int VBO;

glGenBuffers(1, &VBO);
glBindBuffer(GL_ARRAY_BUFFER, VBO);
glBufferData(GL_ARRAY_BUFFER, sizeof(vertices), vertices, GL_STATIC_DRAW);
~~~

~~~c++
glGenBuffers(1, &VBO);
~~~

表示生成一个缓冲区名称，把其编号保存到 `VBO` 里；`VBO` 变量本身只是一个 ID，不是顶点数据。存储空间由后面的 `glBufferData` 分配。

~~~c++
glBindBuffer(GL_ARRAY_BUFFER, VBO);
~~~

表示把编号为 `VBO` 的 Buffer 绑定到 `GL_ARRAY_BUFFER` 这个绑定点上，起到一个激活的作用；之后通过这个绑定点操作的，就是当前绑定的 Buffer。

~~~c++
glBufferData(GL_ARRAY_BUFFER, sizeof(vertices), vertices, GL_STATIC_DRAW);
~~~

四个参数为 目标、大小、数据、使用方式，上述代码表示：给当前绑定的顶点 Buffer 分配足够空间，把 `vertices` 数组复制进去，并告诉 OpenGL 这份数据之后基本不会修改

```c++
glBufferData(
    target,
    size,
    data,
    usage
);
```

最后还有一个删除的函数：

```c++
glDeleteBuffers(1, &VBO);
```
# VAO

VBO 存数据，VAO 记录“这些数据该怎么喂给 Vertex Shader”。

一般是先创建一个 VAO ，得到其 ID，跟 VBO 很像

```c++
unsigned int VAO;
glGenVertexArrays(1, &VAO);
```

然后启用他，表示接下来我要配置这个 VAO

```c++
glBindVertexArray(VAO);
```

然后绑定 VBO ：

```c++
glBindBuffer(GL_ARRAY_BUFFER, VBO);
```

告诉 VAO 怎么读取：

```c++
glVertexAttribPointer(
    0,
    3,
    GL_FLOAT,
    GL_FALSE,
    3 * sizeof(float),
    (void*)0
);
glEnableVertexAttribArray(0);
```

这里表示 `location = 0` 的属性，从 VBO 的开头读，每次 3 个 float，每隔 3 个 float 读下一组。前面的顶点数组只存位置，所以步长是 `3 * sizeof(float)`；如果每个顶点存的是“位置 3 个 float + 颜色 3 个 float”，步长才是 `6 * sizeof(float)`。

最后删除：

```c++
glDeleteVertexArrays(1, &VAO); // 删除
```

# 顶点着色器

作用是 对每一个顶点进行处理，最核心的是计算这个顶点最终的位置

比如最基础的顶点着色器：

```c++
#version 330 core

layout (location = 0) in vec3 aPos; // 从第 0 号属性通道拿数据，输入为 3 维，不是第 0 个顶点

void main()
{
    gl_Position = vec4(aPos, 1.0); // 输出裁剪空间位置，还不是屏幕像素坐标
}
```

# 编译着色器

我们可以理解为，我们已经写好了 GLSL 代码，但 GPU 不能直接拿字符串执行，所以要先“创建 Shader 对象 → 塞源码 → 编译”

这些 GLSL 代码本质上在 C++ 里只是一段字符串

第一步：创建一个顶点着色器对象

```c++
unsigned int vertexShader;
vertexShader = glCreateShader(GL_VERTEX_SHADER);
```

第二步：把源码给这个 Shader 

```c++
glShaderSource(
    vertexShader, // 给哪个 Shader 对象
    1, // 传几段字符串
    &vertexShaderSource, // Shader 源码在哪里
    NULL // 不提供长度数组，源码字符串需要以空字符结尾
);
```

第三步：当然就是编译这个顶点着色器

```c++
glCompileShader(vertexShader);
```

最后还需要检查是否成功

```c++
int success;
char infoLog[512];

glGetShaderiv(vertexShader, GL_COMPILE_STATUS, &success);

if (!success)
{
    glGetShaderInfoLog(
        vertexShader,
        512,
        NULL,
        infoLog
    );

    std::cout << "ERROR::SHADER::VERTEX::COMPILATION_FAILED\n"
              << infoLog << std::endl;
}
```

# 片段着色器

顶点着色器决定“点在哪”，片段着色器计算“片段输出什么颜色”。片段还要经过后续测试、混合等操作，所以这个输出不一定就是最终屏幕颜色。

比如如下最基础的片段着色器代码：

```c++
#version 330 core

out vec4 FragColor; // 表示输出

void main()
{
    FragColor = vec4(1.0f, 0.5f, 0.2f, 1.0f);
}
```

片段着色器的流程与顶点着色器基本上差不多，编译后也需要检查 `GL_COMPILE_STATUS`。

```c++
unsigned int fragmentShader;
fragmentShader = glCreateShader(GL_FRAGMENT_SHADER);

glShaderSource(
    fragmentShader,
    1,
    &fragmentShaderSource,
    NULL
);

glCompileShader(fragmentShader);
```

# 元素缓冲对象 EBO

VBO 存的是顶点数据，EBO 存的是顶点编号，作用是复用顶点，避免重复存储

最简单就是比如我们要画一个矩形如下

```
3 -------- 2
| \        |
|   \      |
|     \    |
|       \  |
0 -------- 1
```

如果没有 EBO ，我们就要写 6 个顶点，但是有顶点被复用了，所以我们可以用 EBO 写索引数组，然后记录 4 个顶点即可，如索引数组

```c++
unsigned int indices[] = {
    0, 1, 3,
    1, 2, 3
};
```

首先是创建

```c++
unsigned int EBO;
glGenBuffers(1, &EBO);
```

然后绑定

```c++
glBindBuffer(GL_ELEMENT_ARRAY_BUFFER, EBO);
```

然后上传数据

```c++
glBufferData(
    GL_ELEMENT_ARRAY_BUFFER,
    sizeof(indices),
    indices,
    GL_STATIC_DRAW
);
```

# 最后怎么串起来用

前面其实是在准备两样东西：**顶点数据，以及处理这些数据的程序。最后通过绘制调用，把它们接起来。**

## 数据这条线：VBO + VAO + EBO

| 部分 | 负责什么 | 可以理解成 |
| --- | --- | --- |
| VBO | 保存顶点的位置、颜色等数据 | 原始数据 |
| VAO | 记录从哪个 VBO、按什么格式读取顶点属性 | 数据读取说明 |
| EBO（可选） | 保存顶点索引，指定使用哪些顶点、按什么顺序使用 | 顶点使用顺序 |

比如画一个矩形：VBO 存 4 个角的位置，VAO 说明每个位置由 3 个 float 组成、送到 `location = 0`，EBO 存 `0, 1, 3, 1, 2, 3`，让这 4 个顶点组成两个三角形。

注意，这个矩形需要另外准备 4 个顶点，不能直接使用开头只有 3 个顶点的数组。这组索引对应的公共边是 `1—3`。

**VAO 不保存顶点数据本身，它保存读取配置，以及相关缓冲区的关联。**

配置时的关键顺序是：

```c++
glBindVertexArray(VAO);

glBindBuffer(GL_ARRAY_BUFFER, VBO);
// 在这里上传顶点数据

glVertexAttribPointer(0, 3, GL_FLOAT, GL_FALSE,
                      3 * sizeof(float), (void*)0);
glEnableVertexAttribArray(0);

// 如果使用索引绘制，在当前 VAO 绑定时绑定 EBO，并上传索引
glBindBuffer(GL_ELEMENT_ARRAY_BUFFER, EBO);
// 在这里上传索引数据

glBindVertexArray(0);
```

`glVertexAttribPointer` 会把当时绑定的 VBO 与对应属性关联起来。`glBindBuffer(GL_ELEMENT_ARRAY_BUFFER, EBO)` 则让当前 VAO 记住 EBO 的绑定；不要在这个 VAO 仍绑定时把 EBO 解绑，否则会清掉这个关联。

VAO 中的 `glVertexAttribPointer(0, ...)` 和顶点着色器中的 `layout(location = 0)` 对应。这里的 0 是属性通道编号，每个顶点的位置都会通过这个通道传给 `aPos`。

## 程序这条线：两个着色器链接成 Shader Program

两个着色器分别编译成功后，还要链接成一个完整程序：

```c++
unsigned int shaderProgram = glCreateProgram();

glAttachShader(shaderProgram, vertexShader);
glAttachShader(shaderProgram, fragmentShader);
glLinkProgram(shaderProgram);

// 检查链接是否成功，使用前面定义的 success 和 infoLog
glGetProgramiv(shaderProgram, GL_LINK_STATUS, &success);
if (!success)
{
    glGetProgramInfoLog(shaderProgram, 512, NULL, infoLog);
    std::cout << "着色器程序链接失败：\n" << infoLog << std::endl;
}
```

编译是分别处理各个着色器，链接是把它们组合成一个程序。链接成功后，`shaderProgram` 就包含顶点处理和片段着色的逻辑。

## 每一帧：选程序、选 VAO、发出绘制命令

前面的创建、上传、配置、编译、链接，通常在渲染循环之前完成。每一帧真正画图时：

```c++
glClear(GL_COLOR_BUFFER_BIT);

glUseProgram(shaderProgram); // 使用哪套着色器
glBindVertexArray(VAO);      // 使用哪套顶点读取配置

// 使用配置了矩形顶点和 EBO 的 VAO
glDrawElements(
    GL_TRIANGLES,           // 每 3 个索引组成一个三角形
    6,                      // 读取 6 个索引，不是 6 个不同顶点
    GL_UNSIGNED_INT,        // 索引类型
    (void*)0                // 从 EBO 的开头读取
);
```

如果画的是开头那个没有 EBO 的三角形，就用配置了那 3 个顶点的 VAO，并把绘制调用换成：

```c++
glDrawArrays(GL_TRIANGLES, 0, 3); // 从第 0 个顶点开始，使用 3 个顶点
```

绘制后还需要由窗口库交换缓冲来显示画面，并处理窗口事件。例如使用 GLFW 时，在循环中调用 `glfwSwapBuffers(window)` 和 `glfwPollEvents()`。

## 一次绘制的完整流程

```text
发出绘制命令
    ↓
确定使用哪些顶点
（DrawArrays 按顺序；DrawElements 按 EBO 索引）
    ↓
按 VAO 的配置，从 VBO 读取顶点属性
    ↓
顶点着色器：计算各顶点的裁剪空间位置，写入 gl_Position
    ↓
图元装配、裁剪、透视除法、视口变换、光栅化
（把顶点组成三角形，得到三角形覆盖的片段）
    ↓
片段着色器：计算片段颜色
    ↓
经过后续测试、混合等操作，写入帧缓冲
    ↓
交换缓冲，显示画面
```

**VBO 存数据，VAO 说明怎么读，EBO 决定取哪些顶点，Program 决定怎么处理，Draw 命令让整套流程开始运行。**
