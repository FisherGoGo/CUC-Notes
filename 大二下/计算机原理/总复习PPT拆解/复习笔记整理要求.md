# 计算机原理总复习笔记整理要求

## 总体目标

根据老师的总复习 PPT，按章节整理计算机原理复习笔记。笔记服务于期末复习，不追求教材式展开，只要求 PPT 中出现的知识点总结准确、清楚、方便背诵和查阅。

## 整理方式

- 按章节整理，不再逐页零散记录。
- 每一章单独建一个 Markdown 文件，放在 `大二下/计算机原理/总复习PPT拆解/` 中。
- 文件命名示例：
  - `第1章 计算机基础与数制.md`
  - `第2章 16位和32位微处理器.md`
- 用户发来某章 PPT 页面时，将内容追加到对应章节文件。
- 如果进入新章节，先新建对应章节文件。

## 内容深度

- 以 PPT 知识点为准，准确总结即可。
- 默认从简，不做过度展开。
- 考试难度不是特别高，普通概念不需要写成教材式长解释。
- 用户明确说“讲讲”“重点讲”时，再适当展开。
- 用户说“简单写写”时，只写核心定义、公式、表格和易错点。

## 写作格式

- 使用纯 Markdown，不使用 HTML 语法。
- 不使用 `<span>`、`class`、HTML 标签等样式写法。
- 重点词用 Markdown 加粗，例如：`**段基址**`。
- 重要程度直接写在标题后，例如：
  - `### 原码、反码、补码（必考）`
  - `### BCD 码（了解）`
  - `### 逻辑地址和物理地址（重点）`
- 公式可以用 Markdown/LaTeX，但不要放进 HTML 标签里。
- 表格优先用于对比类知识点。
- 图片使用 Markdown 图片语法：
  - `![说明](../assets/Note/图片名.png)`

## 笔记结构

每个知识点尽量使用以下结构：

```md
## 知识点名称

### 小标题（重点/必考/了解）

- 简洁定义
- PPT 中的关键说法
- 必要公式或表格
- 易错提醒
```

## 讲解要求

- 回复用户时先简短讲清当前页。
- 再说明已经追加到哪一个章节文件。
- 用户没要求展开时，不要写太长。
- 用户有疑问时，再针对疑问详细讲。
- 对计算、地址转换、原码反码补码、控制信号等容易混的内容，可以多给一个小例子。

## 图片处理

- 用户说图片已存在 `assets/Note` 时，先查看该目录中文件名。
- 将图片插入对应章节笔记。
- 图片路径相对章节文件通常写作：

```md
![图片说明](../assets/Note/文件名.png)
```

## 已确认的偏好

- 不再使用 HTML 语法。
- 笔记要简洁、准确、贴 PPT。
- 不需要把每个概念都讲得很深。
- 遇到用户说“这个我不会”或“讲讲这里”时，再展开解释。
- 同一章内容统一写入该章文件，不另开零散“逐页答疑”文件。
