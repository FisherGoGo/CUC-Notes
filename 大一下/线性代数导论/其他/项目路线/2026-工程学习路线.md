## 二、三阶段路线图

### 阶段一：工程基础补全（预计 2-3 周）

> 目标：把「会写代码」升级为「能交付工程」

| # | 项目 | 技术栈 | 对口岗位点 |
|---|------|--------|------------|
| 1 | **RESTful API 服务** — 简易博客/任务管理后端 | Go + Gin + SQLite + Docker | 后端开发（Go 栈） |
| 2 | **前端管理面板** | React + TypeScript + Vite | 前端/全栈 |
| 3 | **CI/CD 部署流水线** | GitHub Actions + Docker Compose | DevOps 基础 |

**为什么选 Go 而不是 Java？**
- 校招报告推荐：Go 实现「简易 RPC 框架」是头部企业面试亮点
- Go 简洁，2-3 周完成全链路；Java 生态太重，短期产出不划算

**为什么带 TypeScript / React？**
- TS 渗透率超 80%，默认要求而非加分项
- 数字媒体技术专业 UI/UX 方向天然需要前端能力

---

### 阶段二：深度项目（预计 4-6 周）

> 做面试中的「杀手锏」—— 以下二选一，优先 A

#### 🔵 路线 A：后端 / 基础设施（推荐优先）

**项目：简易 RPC 框架（Go）**

```
├── 服务注册与发现
├── 多种序列化（Protobuf / JSON）
├── 负载均衡策略
├── 超时控制 + 熔断
├── 单元测试 + 压测数据
└── 完整 README + 架构设计文档
```

- 直接引自校招报告推荐，面试说服力极强
- 完整度 > 复杂度

#### 🟢 路线 B：实时图形 / 音频引擎（差异化竞争）

**项目：简易音频可视化引擎（C++ / Rust）**

```
├── 实时 FFT 频谱分析
├── OpenGL / Vulkan 渲染管线
├── MIDI 信号解析
├── 可嵌入 Web 的 WASM 版本
└── 完整技术文档
```

- 同时覆盖：C++ 系统编程 + 图形学 + 音频处理 + WebAssembly
- 游戏引擎 / 音视频 / XR 方向稀缺作品，与数媒专业高度吻合

## 三、技术栈全景

```
编程语言：  Go（主力） → Rust（进阶） → C++（图形方向保持）
前端：      TypeScript + React + Vite
后端：      Go + Gin + gRPC/Protobuf
数据库：    SQLite → PostgreSQL
容器化：    Docker + Docker Compose
CI/CD：     GitHub Actions
图形：      OpenGL / WASM（路线 B）
```

---

## 四、执行建议

1. **阶段一立即启动**：Go 语法学习 + Gin 框架 + 第一个 API 服务
2. **每周至少一次 commit**：保持 GitHub 活跃度，本身就是面试加分
3. **不追求完美**：先跑通 MVP，再迭代完善
4. **路线 A 做完再做 B**：一个深度项目 >> 两个半成品
