# 2026 后端 API 项目入门计划

> 开始日期：2026-06-10  
> 周期：2 周主线 + 1 周缓冲/进阶  
> 项目：ACM 训练记录 API  
> 技术栈：Go + Gin + SQLite + REST API + 基础测试 + README

## 1. 为什么先做这个项目

你现在的优势是 ACM 和 C++ 算法能力，但就业时只说“我会算法”不够。企业更关心你能不能把一个需求拆成接口、数据表、代码结构、测试和文档，最后交付成别人能跑起来的项目。

这个项目的目标不是做一个 Online Judge，而是做一个小型后端服务，用来记录和复盘算法训练：

- 记录题目：平台、题名、链接、难度、标签、AC 状态。
- 记录训练：某天做了哪些题，哪些没补，哪些需要复习。
- 查询统计：本周做题数、AC 数、待补题数、薄弱标签。
- 输出接口：用 REST API 暴露新增、查询、更新、统计等能力。

这个题材适合你，因为它能把 ACM 背景转换成工程项目叙事：我不仅会刷题，还能围绕自己的训练流程做一个可维护的小系统。

## 2. 最终验收目标

第 14 天主线完成时，至少做到：

- 本地能运行一个 Go 后端服务。
- SQLite 能持久化保存题目和训练记录。
- README 能指导别人从零跑通项目。
- 核心 API 能用 curl、Postman 或 VS Code REST Client 测试。
- 至少有 3-5 个基础测试。
- 能用 1 分钟讲清楚项目背景、技术栈、接口和你学到的东西。

第 21 天如果有余力，补一个进阶项：

- Docker 化。
- API 文档。
- 更完整的统计接口。
- 简单前端管理面板的设计草稿。
- 3 分钟面试讲稿。

## 3. 项目边界

第一版不做：

- 登录注册。
- 权限系统。
- 前端页面。
- 云部署。
- Online Judge 判题。
- 复杂图表。

第一版只做“能记录、能查询、能统计、能讲清楚”的后端项目。短期入门最怕目标太大，先交付完整小项目，比半成品大项目更有价值。

## 5. 技术栈选择

### Go

Go 语法简单，适合短时间做出后端服务。你有 C++ 和 ACM 基础，上手 Go 的变量、结构体、函数、切片、map、错误处理会比较快。

### Gin

Gin 是 Go 常用 Web 框架，入门成本低。第一阶段只需要掌握：

- 路由。
- 读取路径参数。
- 读取 JSON 请求体。
- 返回 JSON。
- 基础中间件。

### SQLite

SQLite 不需要单独安装数据库服务，适合第一个项目。第一版只需要一份本地 `.db` 文件，就能练到 SQL、持久化、查询和统计。

### REST API

REST API 是后端入门最直接的切入点。这个项目的重点不是框架炫技，而是把资源建模清楚：题目是一个资源，训练记录是一个资源，统计是由数据计算出来的结果。

## 6. 数据模型草稿

### Problem

题目记录：

- `id`：题目 ID。
- `title`：题名。
- `platform`：平台，例如 Codeforces、AtCoder、洛谷。
- `url`：题目链接。
- `difficulty`：难度，可先用字符串。
- `tags`：标签，可先用逗号分隔字符串。
- `status`：`todo`、`ac`、`review`。
- `note`：复盘笔记。
- `created_at`：创建时间。
- `updated_at`：更新时间。

### Session

训练记录：

- `id`：训练 ID。
- `date`：训练日期。
- `title`：训练名称，例如“Codeforces VP 900-1300”。
- `summary`：训练总结。
- `created_at`：创建时间。

### SessionProblem

训练和题目的关联：

- `session_id`：训练 ID。
- `problem_id`：题目 ID。
- `result`：本次训练结果，例如 `ac`、`wa`、`upsolve`。

第一版也可以先不拆关联表，直接在 `sessions` 里记录题目 ID 列表。更推荐使用关联表，因为面试时更容易讲清楚数据库建模。

## 7. API 设计

第一版至少实现：

| 方法 | 路径 | 作用 |
|---|---|---|
| `POST` | `/problems` | 新增题目 |
| `GET` | `/problems` | 查询题目列表 |
| `GET` | `/problems/:id` | 查看题目详情 |
| `PATCH` | `/problems/:id` | 更新题目状态、标签、备注 |
| `POST` | `/sessions` | 新增训练记录 |
| `GET` | `/sessions` | 查询训练记录 |
| `GET` | `/stats/weekly` | 查看本周统计 |
| `GET` | `/reviews/pending` | 查看待补题或待复习题目 |

统一返回 JSON。错误时也返回 JSON，例如：

```json
{
  "error": "problem not found"
}
```

## 8. 14 天主线计划

### Day 1：Go 环境和最小程序

目标：知道 Go 项目怎么运行。

- 安装并确认 Go 环境。
- 跑通 `go version`。
- 写一个 hello world。
- 看 Go Tour 的变量、函数、结构体部分。

验收：

- 能执行 `go run main.go`。
- 能解释 `package main`、`func main()`、结构体大概是什么。

### Day 2：HTTP 和项目需求

目标：知道后端 API 到底在做什么。

- 理解 `GET`、`POST`、`PATCH`、`DELETE`。
- 写下项目要解决的问题：记录 ACM 训练过程。
- 写 5 个核心接口草稿。

验收：

- 能用自己的话解释：前端或客户端发请求，后端处理数据并返回 JSON。

### Day 3：Gin 跑通

目标：有一个能访问的后端服务。

- 创建 Go module。
- 安装 Gin。
- 跑通 `/ping`。
- 写一个返回假数据的 `/problems`。

验收：

- 浏览器或 curl 访问 `/ping` 能看到 JSON。

### Day 4：题目资源建模

目标：实现新增题目的内存版接口。

- 定义 `Problem` 结构体。
- 实现 `POST /problems`。
- 实现内存数组保存题目。
- 用 curl 或 REST Client 测试。

验收：

- 能新增题目。
- 能查询题目列表。

### Day 5：接入 SQLite

目标：数据能持久保存。

- 学 Go 官方数据库教程的核心部分。
- 创建 SQLite 数据库。
- 创建 `problems` 表。
- 写数据库初始化代码。

验收：

- 重启服务后，数据库文件仍在。

### Day 6：题目查询接口

目标：题目 CRUD 的查询部分可用。

- 实现 `GET /problems`。
- 实现 `GET /problems/:id`。
- 支持按状态筛选。

验收：

- 查询列表、详情、空列表、非法 ID 都有合理返回。

### Day 7：第一周复盘

目标：停下来整理，不盲目往前堆。

- 写 README 第一版。
- 整理已完成接口。
- 提交一次 Git commit。

验收：

- README 至少包含项目简介、运行方式、接口列表。

### Day 8：题目更新接口

目标：题目状态能更新。

- 实现 `PATCH /problems/:id`。
- 支持更新 AC 状态、补题状态、标签、备注。
- 处理非法 ID。

验收：

- 能把题目从 `todo` 改成 `ac` 或 `review`。

### Day 9：训练记录建模

目标：把单题记录扩展成训练记录。

- 设计 `Session`。
- 创建 `sessions` 表。
- 设计训练和题目的关联方式。

验收：

- 能讲清楚“题目”和“训练记录”为什么不是同一个表。

### Day 10：训练记录接口

目标：训练记录能新增和查询。

- 实现 `POST /sessions`。
- 实现 `GET /sessions`。
- 给训练记录加日期。

验收：

- 能记录某天做了一组题。

### Day 11：周统计接口

目标：项目开始有“业务价值”。

- 实现 `GET /stats/weekly`。
- 返回本周做题数、AC 数、待补题数。
- 有余力就增加标签分布。

验收：

- 能从已有数据算出统计结果。

### Day 12：待补题接口和错误处理

目标：接口更像真正项目。

- 实现 `GET /reviews/pending`。
- 统一错误返回 JSON。
- 增加基础参数校验。

验收：

- 待补题能被筛选出来。
- 错误不会直接崩服务。

### Day 13：基础测试

目标：补一点工程化能力。

- 写 3-5 个基础测试。
- 手动跑通所有接口。
- 整理示例请求和响应。

验收：

- 能运行 `go test ./...`。

### Day 14：README 和项目讲法

目标：把代码变成能展示的作品。

- 完善 README。
- 写项目复盘。
- 准备 1 分钟项目介绍。
- 提交 Git commit。

验收：

- 别人只看 README 就能知道项目是什么、怎么跑、有哪些接口。

## 10. 面试时怎么讲

1 分钟版本：

> 我用 Go 和 Gin 做了一个 ACM 训练记录 API，用 SQLite 存储题目、训练记录和补题状态。这个项目是为了解决我自己训练复盘分散的问题。它支持新增题目、查询题目、更新 AC 和补题状态、记录训练，以及统计本周训练情况。这个项目让我从只会写算法，开始接触接口设计、数据库建模、错误处理、测试和 README 文档。

## 11. 执行原则

- 每天优先完成任务清单里的 `[P0]`。
- 少数只有 1 小时的日子，只做最小任务，不补课焦虑。
- 不要一开始追求架构优雅，先跑通，再整理。
- 每 3-4 天提交一次 Git。
- 每周至少写一次复盘，记录你踩坑和解决方式。

## 12. 最小成功标准

如果期末周压力大，最低只要做到下面这些，也算成功：

- Go 服务能启动。
- `problems` 表能保存题目。
- 能新增、查询、更新题目。
- README 写清楚怎么运行。
- 有一次完整 Git 提交。

这已经比“只看教程”强很多，因为你至少亲手完成了一个可运行项目。
